# E2E Test Infra: Phase 298 Dynamic Strategy Mining & Microstructure Mutation

## Test Philosophy
- Opaque-box, requirement-driven testing derived strictly from `ORIGINAL_REQUEST.md` and user-facing specifications.
- Complete coverage across all 16 features in `PROJECT.md § Feature Inventory`.
- Strict mathematical verification of balance conservation ($|\Delta| < 10^{-15}$ USDT).
- Offline, deterministic execution: zero live network calls, zero unapproved LLM calls, zero private keys.
- Systematic 4-tier methodology:
  - Tier 1: Feature Coverage (>=5 test cases per feature)
  - Tier 2: Boundary & Corner Cases (>=5 test cases per feature)
  - Tier 3: Cross-Feature Combinations (pairwise interactions)
  - Tier 4: Real-World Application Scenarios (comprehensive integration)
  - Tier 5: Adversarial Coverage Hardening (white-box stress testing via Challenger)

## Test Architecture
- Test runners:
  - Backend: `uv run pytest tests/unit/test_phase_298_strategy_mining.py tests/unit/test_phase_298_strategy_mining_api.py`
  - Integration: `uv run python scripts/run_phase_298_strategy_mining.py` (4 deterministic tracks)
  - Frontend: `npm test` inside `frontend/` (Vitest)
  - Static: `uv run ruff check src scripts tests`, `uv run mypy src/autonomous_futures/feed/strategy_mining.py`
- Test case format:
  - Unit tests use synthetic fixtures (`_make_depth`, `_make_trade`, `_make_mark`) and temporary mock manifests.
  - Integration runner exercises real pipeline components against cached market structures.
